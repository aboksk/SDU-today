# Архитектурные решения

## Первый backend-этап

- API — один NestJS-модульный REST-сервис. Отдельные сервисы и очереди не нужны для учебного объёма.
- PostgreSQL запускается локально через Compose; Prisma управляет схемой, миграциями и запросами.
- Пользовательские и переводимые тексты представляются обычными колонками и JSON-объектами соответственно.
- `Event.capacity` и `Event.soldCount` хранят вместимость и занятые места. SQL CHECK в миграции обеспечивает `0 <= soldCount <= capacity`.
- `FloorPlan` обозначает блок и этаж; координаты мест и кабинетов хранятся в `Location` в системе координат исходной карты `1382 × 2576`.
- `/locations` использует сильный SHA-256 ETag от стабильного JSON-ответа.
- `legacy-prototype/` — неизменённая копия прототипа для сверки и сохранения исходных данных.
- Vitest покрывает HTTP-контроллеры с подменённым Prisma; отдельный интеграционный тест проверяет CHECK constraint на настоящей PostgreSQL.

## Этап регистрации и входа

- Frontend — небольшой React-клиент в ранее пустом `apps/web/`; существующий прототип не переносится и не заменяется.
- Пароли хранятся как bcrypt-хеши. Сервер проверяет формат и домен email, длину пароля, совпадение подтверждения и уникальность адреса.
- Сессии хранятся в PostgreSQL через Prisma. Браузеру выдаётся случайный токен в HttpOnly cookie, а база хранит только SHA-256-хеш токена и срок действия.
- Cookie использует `SameSite=Lax`; `Secure` включается в production по `NODE_ENV=production`. CORS разрешает origin из `WEB_ORIGIN` и credentials.
- Email-домен SDU является ограничением регистрации, но не подтверждением владения адресом.
- React-клиент использует те же `/news`, `/events`, `/locations` и `/auth/me` endpoints; прототип и карта сохранены, map places загружаются из PostgreSQL.
- `EventRegistration` имеет уникальный ключ пользователя/мероприятия. Запись атомарно увеличивает `Event.soldCount` только при доступном месте и создаётся в той же транзакции.
- Создавать события может только участник `ClubMembership` с ролью `ADMIN`; сервер проверяет членство для каждого запроса. Имена участников видны только пользователю с собственной регистрацией на событие; API не раскрывает их email или идентификаторы.
- Для платных мероприятий предусмотрена только учебная имитация оплаты: пользователю показывается сумма и подтверждение, платёжные реквизиты не запрашиваются и деньги не списываются. Backend сохраняет `SIMULATED_PAID` в записи; обычный маршрут записи допускает только бесплатные мероприятия.
- Карта использует координаты общего плана кампуса. Совпадающие координаты аудиторий разных этажей разведены визуально; выбор строки центрирует её на карте, а масштаб сохраняет текущую область просмотра.

## Границы текущего этапа

Подтверждение адреса, сброс пароля, OAuth, защита от массового перебора, отмена записи на мероприятие, реальные платежи и полноценное production-развёртывание frontend не входят в учебный MVP.
