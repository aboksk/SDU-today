# SDU Today

Учебный full-stack проект: исходный статический прототип сохранён в `sdu-today/` и его копии `legacy-prototype/`. REST API находится в `apps/api/`, простой React-клиент — в `apps/web/`.

## Требования

- Node.js 20.19+
- npm 10+
- Docker Desktop с запущенным Linux engine для PostgreSQL

## Первый запуск

Команды выполняются из корня проекта. Скопируйте файл окружения один раз:

```powershell
Copy-Item .\apps\api\.env.example .\apps\api\.env
npm install
npm run db:up
npm run db:migrate
npm run db:seed
```

Откройте два отдельных терминала из корня проекта:

```powershell
npm run api:dev
```

```powershell
npm run web:dev
```

Откройте frontend по адресу `http://localhost:5174`; Swagger UI API — `http://localhost:3000/api/docs`.
Vite использует порт 5174 намеренно и завершит запуск, если он занят. Frontend направляет `/api/*` в NestJS через локальный proxy.
PostgreSQL работает в Docker на порту `5433` хоста (внутри контейнера — `5432`).

## Регистрация и вход

1. В браузере откройте `http://localhost:5174/register`.
2. Заполните имя, адрес вида `name@sdu.edu.kz`, пароль и подтверждение.
3. После сообщения об успешной регистрации перейдите на страницу входа.
4. Войдите с теми же почтой и паролем. После входа появится страница с именем и кнопкой выхода.
5. Нажмите `Log out`; сессия будет удалена на сервере и cookie очищена.

Проверить API вручную можно в Swagger UI или напрямую:

- `GET http://localhost:3000/health`
- `POST http://localhost:3000/auth/register`
- `POST http://localhost:3000/auth/login`
- `GET http://localhost:3000/auth/me`
- `POST http://localhost:3000/auth/logout`
- `GET http://localhost:3000/news`, `/events`, `/locations`
- `GET http://localhost:3000/events/registrations/me` — мои записи (нужна сессия).
- `POST http://localhost:3000/events/:id/register` — запись на мероприятие (нужна сессия).
- `POST http://localhost:3000/events/:id/pay` — тестовая оплата платного мероприятия и запись на него (нужна сессия; деньги не списываются).
- `GET http://localhost:3000/events/:id/attendees` — имена участников (нужна сессия и собственная запись на событие).
- `GET http://localhost:3000/clubs/mine` — клубы текущего пользователя с его ролью.
- `POST http://localhost:3000/clubs/:clubId/events` — создать событие (нужна роль `ADMIN` в этом клубе).

Frontend отправляет запросы через `/api` proxy с `credentials: 'include'`. Для ручного входа напрямую в Swagger браузер должен сохранять cookie.

## Тестовая оплата мероприятий

Для платного мероприятия пользователь сначала видит страницу подтверждения с суммой, а после нажатия «Подтвердить тестовую оплату» записывается на событие. Это учебная имитация: данные банковской карты не запрашиваются, реальный платёжный сервис не подключён и деньги не списываются. Бесплатные события по-прежнему используют обычную запись. Перед запуском обновите базу через `npm run db:migrate`.

## Страницы приложения

- `/` — ближайшие мероприятия и свежие новости из API.
- `/news` и `/news/:id` — список, поиск и полный текст новости из PostgreSQL.
- `/events` и `/events/:id` — мероприятия, вместимость, место и серверная запись пользователя.
- `/my-events` — список записей вошедшего пользователя.
- `/map` — поиск по местам и кабинетам из `/locations` поверх исходной карты кампуса.
- `/organize` — форма создания события для администраторов клубов.
- `/login` и `/register` — вход и регистрация.

Старый полностью статический прототип сохранён в `sdu-today/` и `legacy-prototype/`; его можно открыть напрямую, например `sdu-today/index.html`. Новый React-клиент не меняет его файлы.

## Создание события администратором клуба

Роль проверяет backend по записи `ClubMembership`, а не по данным формы. Новый аккаунт сначала нужно добавить в клуб с ролью `ADMIN`. Это можно сделать доверенным администратором базы данных после регистрации пользователя; следующий SQL добавляет/повышает его в клубе `music`:

```sql
INSERT INTO "ClubMembership" ("userId", "clubId", "role")
SELECT "id", 'music', 'ADMIN'
FROM "User"
WHERE lower("email") = lower('name@sdu.edu.kz')
ON CONFLICT ("userId", "clubId")
DO UPDATE SET "role" = 'ADMIN';
```

После входа администратор увидит раздел «Создать мероприятие». Форма сохраняет русское и английское название/описание, категорию, время, цену, вместимость и место кампуса. Участники могут искать имена других записавшихся только после собственной записи на это мероприятие; email и другие личные данные API не возвращает.

## Миграции и тесты

```powershell
npm run db:migrate
npm test
npm run test:db
npm run web:build
```

`npm test` запускает HTTP-тесты API; `npm run test:db` проверяет ограничения вместимости и уникальность записей непосредственно в PostgreSQL и требует запущенную мигрированную базу. `npm run web:build` проверяет TypeScript и собирает frontend.

Если изменились исходные данные прототипа, запустите `npm run db:import`, затем `npm run db:seed`.

## Как устроены данные и авторизация

REST-запрос приходит в NestJS-контроллер. Для чтения и записи контроллеры используют Prisma Client, а Prisma отправляет SQL в PostgreSQL. `apps/api/prisma/seed.ts` загружает клубы, новости, мероприятия и места прототипа; seed не очищает пользовательские записи.

При регистрации сервер нормализует email и проверяет домен и пароль, затем сохраняет bcrypt-хеш, а не пароль. При входе генерируется случайный токен сессии: браузер получает его только в HttpOnly cookie, а PostgreSQL хранит SHA-256-хеш токена, срок действия и связь с пользователем. Выход удаляет сессию в базе. Cookie имеет `SameSite=Lax`; в production при `NODE_ENV=production` также выставляется `Secure`. Email-домен не означает подтверждение адреса.

`Event.capacity` и `Event.soldCount` защищены SQL CHECK-ограничением `0 <= soldCount <= capacity`. Запись на мероприятие создаётся внутри Prisma-транзакции: сервер атомарно занимает место только пока вместимость не исчерпана, а составной уникальный ключ не позволяет пользователю записаться повторно. `/locations` использует ETag и возвращает `304`, если клиент прислал актуальное значение.

## Что объяснить на защите

- NestJS-модуль объединяет связанные контроллер, сервис и Prisma.
- Prisma-модель описывает таблицы и связи; миграция меняет базу, seed загружает начальные данные.
- Пароль нельзя восстановить из bcrypt-хеша; при входе сервер сравнивает введённый пароль с хешем.
- Сессионный токен находится в HttpOnly cookie, его хеш — в базе. Поэтому frontend не может прочитать cookie из JavaScript, а logout отзывает серверную сессию.
- JSON-поля `title`, `description`, `name` содержат переводы `ru` и `en`.

Подробности решений: [`docs/DECISIONS.md`](docs/DECISIONS.md).
